Windmill 1.840 为作业运行阶段增加断网注解

原文发布 2026-10-18 05:24 · 事件发生 未知 · 评分 3.5 / 5

此前：Windmill10月16日发布1.839.0：新fork的工作空间对象存储默认写入独立前缀，读取可回退祖先数据，列表和删除只作用于本fork；新增Require isolated forks保护规则，可要求对象存储、DuckLake及所属数据表采用隔离或克隆。版本还纳入Teams入站Bot Framework JWT验证修复，相关实现位于企业版。
新增事实：此前1.839为fork对象存储前缀及可配置隔离规则；本次1.840新增作业run-step断网注解、不能沙箱则拒绝的路径，以及已启用沙箱情况下的Bun/npm安装隔离。

FACT / 核心事实

Windmill10月17日发布1.840.0，新增no_network注解，使支持的作业运行阶段进入独立网络命名空间，阻断外网、DNS与本机API，并移除运行环境中的WM_TOKEN；无法进入所需沙箱时拒绝执行。版本还在启用作业沙箱时，将Bun/npm依赖安装放入nsjail，修复Python模块挂载与AI代理路径校验等问题。

ANALYSIS / 为什么重要

昨日更新处理fork数据隔离，本次新增的是运行阶段可主动放弃网络访问，以及依赖安装阶段的系统隔离。对仅处理输入数据的脚本和Agent生成任务，这提供更细的执行权限边界；运维团队仍需分别核对运行、安装及外部服务调用的需要。

ANALYSIS / 技术与商业解读

no_network不覆盖依赖解析和安装，它们仍可联网。Bun/npm安装脚本继续执行，安装时保留网络且仅沙箱已开启时适用；未启用沙箱的worker行为不变。因此不能概括为整条供应链离线，或认为注解能让任意执行器获得同等隔离。 安装隔离可通过DISABLE_BUN_INSTALL_SANDBOX=true显式关闭，需同时检查该配置。

P1重要补录Cloudflare机器人访问治理

Cloudflare为已验证机器人引入持续行为评估，公开评分仍待推出

原文发布 2026-10-16 21:00 · 事件发生 未知 · 评分 3.35 / 5

FACT / 核心事实

Cloudflare介绍对Verified bots持续观察的系统：除确认身份，还评估其是否长期遵守robots.txt，以及收到HTTP 429后是否降低请求速率。系统已用于内部评估，以持续模式而非单次异常形成可解释的信任区间；Radar公开分数与客户可选信任阈值仍是后续计划。

ANALYSIS / 为什么重要

身份验证不等于持续可信，网站需要根据实际访问行为管理自动化流量。该方案将声明、行为与处置连接起来，但不能写成所有客户今天已可使用公开机器人信用分。

ANALYSIS / 技术与商业解读

企业Agent也需要在身份之外保留行为证据和撤销权限的路径。机器人是否遵守访问偏好，可以成为访问治理的一层信号；它不能代替网站授权，也不能保证每次请求安全。

P1重要补录CloudflareWorkers安全网关公测

Cloudflare将Workers接入Gateway策略，Forward进入公测

原文发布 2026-10-16 01:11 · 事件发生 未知 · 评分 3.35 / 5

FACT / 核心事实

Cloudflare宣布Gateway的Forward操作与Workers集成进入公开测试，可把HTTP策略允许且匹配规则的流量送至Worker，处理请求、响应或记录上下文。DLP自定义校验也已提供，用业务自己的数据源验证检测结果。Gateway策略条件中的Custom Functions则预计年底前推出，不能与已公测的Forward混同。

ANALYSIS / 为什么重要

安全团队获得在流量处理路径中加入自有逻辑的入口，可用于上下文补充、告警及敏感信息校验。功能成熟度与执行成本仍需按具体入口判断，不能把整套可编程安全平台一概写成正式可用。

ANALYSIS / 技术与商业解读

自定义逻辑也带来代码错误、外部依赖和敏感数据传递的新责任。应限定处理范围、定义失败行为并验证权限；流量会按标准Worker请求计费，免费额度与执行时限仍适用。
